The server action uses the staff JWT and Storage RLS rather than a service-role key; authorized staff could technically call the same constrained Storage insert API outside the UI, so production hardening may add one-time upload intents if that distinction is required. A rare storage-success/metadata-failure can leave an inaccessible orphan object because application roles intentionally lack delete permission; production should add an audited reconciliation job. Local Storage was exercised through schema/policy tests; no synthetic binary end-to-end browser upload was automated.
