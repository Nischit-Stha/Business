- **Database changes:** Added durable `operational_exceptions` with typed severity/status, entity reference, assignment, resolution, structured metadata, owner-only flag, timestamps, and a partial unique index preventing duplicate unresolved exceptions. Added deny-by-default RLS, admin staff-directory visibility, role-aware exception mutation RPCs, agreement-aware swap/reporting RPCs, an admin-only rerunnable schedule-extension RPC, exception refresh, owner metrics, and expanded audited action types. No prior migration was edited.
- **Features implemented:** Atomic active-agreement vehicle swaps preserve agreement/customer, immutable payment history, schedule, and assignment history while closing/releasing the old vehicle and assigning the available replacement; conflict and odometer checks occur under row locks. Open-ended active agreements maintain a safe 8–12 week minimum through the existing idempotent generator; per-agreement failures are deduplicated into owner-only exceptions. The `/owner` dashboard shows fleet/agreement/overdue metrics and only unresolved attention items ordered by severity then age. Staff can view permitted exceptions, assign them, resolve them with a required note, and administrators can see high-risk owner-only items and manually run the staging-safe schedule extension. Existing detectable exception sources include overdue customers, high balances, awaiting signatures, unallocated funds, schedule failures, swap failures, and active agreement/vehicle inconsistencies. Customer approvals and pickup/return prerequisite exceptions remain supported types but are not synthesized because the current schema has no corresponding approval/prerequisite state.

- **Unresolved issues:** The existing activation path initially generates roughly 26 weeks, so the 12-week maintenance job normally performs a safe no-op until the future horizon drops below its target. There is no current durable customer-approval or pickup/return-prerequisite model to scan. Automatic invocation is documented for local/staging but intentionally not connected. Renta, Starr365, automatic bank/PayID reconciliation, SMS, toll/fine integration, maintenance, and production migration remain out of scope and unimplemented.
- **Security notes:** All state-changing browser workflows call security-definer RPCs that re-check active staff/admin authorization. Exception reads use RLS; owner-only high-risk records require admin. The swap locks agreement, assignment, and vehicles and commits all state changes together. Financial rows are never updated by a swap. Schedule jobs require a dedicated authenticated active admin rather than exposing service-role credentials. Audits record actors and operational identifiers; failure metadata excludes credentials and customer PII. Fixtures are synthetic.
